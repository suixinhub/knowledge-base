# GitHub 能做什么

> GitHub 最容易被误解成"程序员的代码托管网站"。它真正的本质是四个能力，代码只是最初装进去的东西。本库里正在跑的「B站数据每日跟踪」就是这些能力的活例子。

## 一、四个底层能力

**1. 版本控制**（底层是 Git）。它记录的不是"最终稿"，而是每一次改动的差异，以及为什么改。任何能写成文本的东西都适合放进来：文档、配置、脚本、清单、笔记。

**2. 协作流程**。Pull Request 是"我改了一版，你看要不要合并"的正式动作；Issue 是任务、缺陷和讨论的载体；Review 是逐行批注。这套流程的价值不在写代码，而在"改动有记录、决定有依据"。

**3. 自动化**（Actions）。仓库里发生事情就触发云端机器跑脚本：推送后编译、定时抓数据、生成报表、部署网站。这是 GitHub 从"网盘"变成"平台"的关键。

**4. 分发**（Release 与 Pages）。Release 挂文件给别人下载，Pages 把仓库内容直接变成网站。本库资料分类里那份《高性价比人生指南》PDF，原作者就是把成品挂在 Release 里，所以能绕过登录直接拿到。

## 二、应用场景

| 场景 | 典型做法 | 本库的例子 |
|---|---|---|
| 代码与项目 | 备份个人项目、多人协作、给开源项目提改进、读别人的代码学方案 | — |
| 网站与内容发布 | 文档站、博客、作品集、简历；Markdown 写完推送即上线 | 本站本身（Pages） |
| 文件与资源分发 | Release 挂 PDF/安装包/数据集，一个链接手机就能下 | 高性价比人生指南 PDF 就是这么下载的 |
| 自动化小工具 | Actions 定时抓数据、生成报表、自动提交 | [B站数据每日跟踪](../自媒体运营/B站数据跟踪.md) |
| 任务与知识管理 | Issues 当待办清单、Projects 当看板、Discussions 当讨论区 | B站长尾改造清单适合拆成 Issues |
| 学习与参照 | `awesome-xxx` 清单是领域入门索引；工具的 README 和 Issues 比二手教程准 | 找相机固件、开源工具、LUT 资源 |
| 备份与存档 | 文本资产进仓库 = 异地备份 + 完整历史，换电脑 clone 即恢复 | 两个知识库 |

关于"自动化小工具"多说一句：它是个人用户最被低估的一块。比如让 Actions 每天早上抓一次 B站账号的播放数据写成 Markdown 自动提交进仓库，一年后就有完整的趋势记录，而不是靠截图回忆——本库的 `tracker/` 目录 + `bili-tracker` 工作流做的就是这件事。

## 三、不适合的场景（边界）

- **大文件与媒体库**：单文件硬上限 100MB，仓库超过 1GB 就开始难用。视频、图片库不要往里放。
- **需要实时协同的文档**：两人同时改同一段会冲突，要 Git 知识才能解。多人协作用飞书/语雀。
- **涉密数据**：私有仓库也建议脱敏；完全私密的 Pages 站点只有企业版组织能开。
- **当数据库或后端服务**：没有常驻运行环境，Actions 只适合批处理，接不了请求。
- **国内访问**：`github.com` 的 443 端口经常被拦（本机的实际痛点），`api.github.com` 反而通畅。日常改文档走网页或 GitHub App 更稳，`git push` 失败多半是网络而不是操作错误。

## 四、免费额度（2026-11 查证）

| 项目 | 免费额度 |
|---|---|
| 仓库数量 | 公开、私有均无限制 |
| Actions 私有仓库 | 2,000 分钟/月（公开仓库不计费） |
| Pages | 站点上限 1GB，月流量软限 100GB，私有仓库需付费版 |
| 单文件 | 硬上限 100MB，建议 <50MB |
| Codespaces 云端开发环境 | 120 核心小时/月 + 15GB 存储 |

## 五、本库正在跑的实例：B站数据跟踪

`tracker/fetch_bili_stats.py` 每天北京时间 09:30 由本机定时任务触发：

1. 读 `tracker/targets.json` 里的 BV 号清单
2. 逐个调 B站公开接口（`x/web-interface/view`，无需登录），取播放/点赞/投币/收藏/弹幕/评论/分享
3. 追加一行到 `data/stats.csv`（长期流水，可画趋势，同一天重复跑不重复记）
4. 与上次记录比对算增量，重写 [B站数据跟踪](../自媒体运营/B站数据跟踪.md) 快照页
5. 通过 GitHub API 把数据提交回仓库

要加监控视频，往 `targets.json` 的 `videos` 里加一项即可。

**两个实测踩到的坑，比方案本身更有价值**：

1. **B站会拦截海外服务器 IP**。第一版把采集放在 GitHub Actions 上跑（美国机房），8 条视频全部被风控拒绝；换成"本机采集 + API 提交"后一次成功。结论：国内数据源的采集任务别放海外 runner，Actions 适合的是"源站在海外"或"目标服务不挑 IP"的任务。
2. **匿名访问账号级接口会被喂假数据**。用 curl 直接查账号接口，返回了随机昵称和 0 粉丝（连空间页都被替换成假账号），但按 BV 号查单视频的接口是可靠的真实数据（与创作中心后台完全一致）。所以跟踪按视频走，不按账号走。

本地重跑/验证：`python tracker/fetch_bili_stats.py`，然后 `python tools/push_kb.py "commit message"` 推送。
