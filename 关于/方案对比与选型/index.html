    方案对比与选型¶

    选工具这件事没有绝对最优，只有"匹配不匹配"。这一篇把主流方案摊开对比，说清楚为什么最后落在 MkDocs Material + GitHub Pages，以及什么情况下应该换掉它。

    一、先分成四个阵营¶

    知道对方属于哪一类，比记住具体产品名更重要：

    阵营 代表 本质 典型代价
    A. 纯文本 + 自建站 MkDocs Material、Quartz、Docusaurus、GitBook CLI Markdown 存本地/Git，程序编译成网站 要懂一点点命令行和 Git
    B. 本地笔记软件 Obsidian、Logseq、Foam、思源笔记 数据在本机，软件负责编辑与双链 想随时随地看要额外方案；多人协作弱
    C. SaaS 在线文档 Notion、语雀、飞书文档、腾讯文档、FlowUs 数据在厂商服务器，浏览器即用 数据不在自己手里；免费额度有限；导出失真
    D. 自建服务端应用 Outline、AFFiNE、Trilium、Wiki.js、Confluence 自己部署一套带数据库的系统 要买服务器、要运维、要备份

    本知识库属于 A 类。

    二、横向对比总表¶

    打分口径：★★★ = 强项，★★ = 够用，★ = 明显短板。

    维度 MkDocs Material（本方案） Obsidian + Quartz Notion / 语雀 Logseq Outline / AFFiNE
    数据归属 ★★★ 纯文本在你的 Git 里 ★★★ 纯文本在本地 ★ 在厂商服务器 ★★★ 本地纯文本 ★★ 数据库（可自建）
    成本 ★★★ 0 元 ★★★ 0 元（同步/发布另计） ★★ 免费版有限制 ★★★ 0 元 ★ 服务器 + 运维成本
    上手门槛 ★★ 要会 git 基础 ★★★ 装完就能写 ★★★ 打开就能写 ★★ 需理解块引用 ★ 需部署运维
    全文检索 ★★★ 内置，中文可用 ★★★ 本地强，发布版较弱 ★★★ 强 ★★★ 强 ★★★ 强
    手机访问 ★★★ 有网址就能看 ★★ 需 Publish（付费）或 Quartz ★★★ 原生 App ★★ 需同步方案 ★★★ 网页
    版本历史 ★★★ Git 全量 diff ★★★ Git ★★ 有限回溯 ★★★ Git ★★ 应用层历史

    三、逐个说清"为什么不选它"¶

    Obsidian（+ Quartz 发布）¶

    最强的对手，也是最接近的替代品。 本地 Markdown、双链、插件生态、离线完全可用，这些都比本方案更顺手；配 Quartz 也能发布成网站，星标约 1.3 万。

    没选它的原因：它的核心价值在"双向链接 + 图谱"，适合卡片式、发散式的知识网络（原子笔记、灵感串联）。而这个库里的内容是成篇的长文档（包装主数据设计、B站分析报告），是"一章一章的文档"而不是"一张一张的卡片"，双链在这里几乎用不上。为了用不上的功能，去承担"发布链路更绕、主题定制更麻烦"的成本，不划算。

    什么时候该换：如果你的笔记形态变成大量短卡片、需要 [[双向链接]] 和图谱视图，那就搬去 Obsidian，docs/*.md 可以直接放进去打开，零成本迁移。

    Notion / 语雀 / 飞书文档¶

    上手最快，协作最强，手机上体验也最好。

    没选它的原因：三条硬伤。

    1. 数据不在你手里。厂商改定价、砍功能、停服务，你只能被动接受。导出成 Markdown 时，数据库视图、折叠块、公式经常丢结构。
    2. 不适合 AI 批量维护。想给 20 篇文档统一改术语，在 Notion 里要么手动点 20 次，要么调 API 并承担限流，还要小心破坏页面结构。
    3. 样式各自为政。写着写着每页排版都不一样，一年后回看像垃圾场——这是富文本编辑器的通病。

    什么时候该换：需要多人同时编辑、需要审批流、需要给非技术同事看。那就用飞书/语雀，别硬撑。

    Logseq¶

    本地优先、大纲式、双链强。适合"每天记流水、靠引用串起来"的日志型知识管理。同样不适合成篇长文档，且发布成网页的链路比 MkDocs 麻烦。

    Outline / AFFiNE / Trilium¶

    功能最全，但都需要一台服务器：买 VPS、装 Docker、配 HTTPS、定期备份、盯安全更新。个人知识库到这个体量是过度工程——你花在运维上的时间会远超写内容的时间。

    GitBook / Docusaurus¶

    同样是"文档站"思路。GitBook 现在强绑定其 SaaS；Docusaurus 更适合技术产品的开发者文档（React 生态、版本化 API 文档），配置复杂度高于 MkDocs。MkDocs Material 是这一类里"配置最简、开箱最好看"的那个：一份 YAML + 一个文件夹，就能出成品。

    为什么 MkDocs Material 是这个阵营的第一名¶

    按 GitHub 星标（2026 年 11 月查询，约值）：

    项目 星标 定位
    squidfunk/mkdocs-material 约 2.76 万 文档站主题（本方案）
    foambubble/foam 约 1.75 万 VS Code 里的知识管理
    jackyzha0/quartz 约 1.36 万 Obsidian 笔记发布成站
    mkdocs/mkdocs 约 1.9 万 底层生成器

    星标不等于一切，但在这个细分里它领先幅度很大，意味着：文档齐全、问题好搜、插件生态成熟、长期有人维护。

    四、这个方案的真实优势（按重要性排序）¶

    1. 数据是真的属于你。全部是 .md 文本 + 一个 YAML 配置，存在你自己的 GitHub 仓库里。哪天不想用了，把文件夹拷走，任何编辑器都能打开，一个字都不会丢。
    2. 零成本、零运维。公开仓库的 Pages 和 Actions 都在免费额度内。没有服务器要续费，没有证书要更新，没有数据库要备份。
    3. 一次配置，永久一致。全站样式由主题统一控制，不存在"这页排版好看那页难看"。想换风格改配置，全站同步变。
    4. 手机随时能看，还能直接下载附件。发个链接就行，不用装 App、不用登录。PDF 这类大附件也能直接点开下载。
    5. 天然适合我来维护。纯文本 + 明确的目录规则 + Git diff，意味着"帮我把这批文档统一改写"这类任务是可安全执行的：改错了能一条命令回滚，改动范围一目了然。
    6. 写作时不需要分心排版。只写 Markdown 语义，样式自动套。写内容时不用想"这段该用什么字号"。

    五、这个方案的真实劣势（不粉饰）¶

    1. 有技术门槛。至少要知道 git add / commit / push 三件事，或者每次都来找我代劳。纯小白第一次用会卡在命令行。
    2. 发布有延迟。从推送到网站更新要 1~2 分钟，不是"边写边同步"。
    3. 没有协作能力。两个人改同一篇会冲突，且冲突要靠 Git 解决。它本质是"个人"知识库。
    4. 不支持细粒度权限。仓库公开 = 全世界可读；仓库私有 = 网站发不出去（免费账号）。没有"部分公开"这种选项。
    5. 搜索索引随规模膨胀。几百篇以上时，首屏要下载的索引会明显变大（目前十几篇，无感）。
    6. 图片管理靠手工。没有拖拽上传，要自己把文件放进 assets/ 再写路径。

    六、决策建议：什么情况选什么¶

    按你当下的处境对号入座：

    需要多人同时编辑 / 给同事看？
├─ 是 → 飞书文档 / 语雀（别用本方案）
└─ 否 ↓

内容以大量短卡片和双链为主？
├─ 是 → Obsidian（本地）+ Quartz（发布）
└─ 否 ↓

主要是成篇的长文档，要一个固定网址、要手机能看？
├─ 是 ↓
│   愿意碰一点 Git？
│   ├─ 是 → MkDocs Material（本方案）✅
│   └─ 否 → Notion / 语雀（牺牲数据归属换便利）
└─ 否 → 一个文件夹 + 全文搜索工具就够了，不必建站

    给这个库的结论：内容偏方法论长文档、需要随时手机翻阅和下载附件、需要 AI 参与批量维护、不需要多人协作、预算为零——五项全部指向 MkDocs Material。唯一要接受的门槛是 Git，而这一步可以完全交给我。

    七、如果以后要迁移，成本有多大¶

    这是选型时最少被考虑、事后最痛的一项。本方案的迁移成本极低：

    迁到哪 要做的事 工作量
    Obsidian 把 docs/ 整个文件夹拖进 Obsidian 库 5 分钟
    Notion / 语雀 逐篇导入 Markdown（表格能保留，格式基本正确） 半小时
    其他静态站生成器（Docusaurus/VitePress） 复制 docs/，重写配置和导航 半天
    换电脑 / 换账号 git clone 到新机器 2 分钟

    反过来，从 Notion 迁出来是最麻烦的：数据库视图会退化成普通表格，折叠块和 callout 会丢失，内链常断。数据放在纯文本里，等于把"以后想换"这个选项永久保留着——这是本方案最被低估的价值。
